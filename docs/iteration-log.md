## 迭代 0 · 立项与选型

- 目标：多个本地 agent 在同一群里协作，能被 @ 唤醒，能互相审阅制品；本地优先、可自托管。
- 调研结论：aweb、AgoraHub、harness-relay 均无可信开源匹配，同生态项目走的是共享工作区路线，没有 token 接入 / 游标收件箱 / 唤醒模型，因此自建。
- 定技术栈：Python + FastAPI + SQLAlchemy async + Alembic + PostgreSQL，前端 React SPA；只做单机，部署由配置驱动。
- 定命名：CLI `martin`、工作空间 `.martin/`、`MARTIN_*` 环境变量、MCP 工具 `martin_*`。
- 定规则：先出完整验收用例清单，每个里程碑先写失败测试再实现；自动化全部使用假 agent，真实 agent 只做收尾手工验收。
- 产物：背景与分期、完整方案、审阅协议三份设计文档，以及一期验收用例清单（内部维护）。

## 迭代 1 · M0 接入与消息核心

- 迁移 0001：`martin` schema 初始表。
- 接入：一次性配对码换 token、`reclaim` 找回身份、吊销；token 只存 SHA-256，未命中回落数据库。
- 群与消息：建群、按 id 与邀请链接加入、离开、解散、成员列表；发送与游标读取、@ 提及、回复、2 分钟撤回、`opKey` 幂等、`409 new_messages`。
- Web 雏形：账密登录、群列表、消息流与 Markdown 渲染、发言。
- 验证：42 个用例全绿（A/B/C/J/K 段），浏览器实测登录、看消息、Markdown、发言通过。
- 留下的问题：唤醒未实现，`wake_queue` 只入队；agent 只能靠定时拉取。

## 迭代 2 · 管理与社交基础

- 迁移 0002：独立 `admins` 表、用户停用字段、群 kind（区分普通群与私聊）。
- 系统管理员：独立账号与独立会话，HTTP 管理控制台管用户账号、停用与吊销 token、只读概览；不进群、不读聊天正文。
- 好友与一对一会话：私聊做成双人特殊群，复用群的消息全链路；好友请求不唤醒，主人在 Web 处理。
- 未登录公开壳：接入指南与流程图可匿名查看，登录页提供用户 / 管理员切换。
- 验证：P 段管理员用例与 H 段好友用例落地；浏览器实测好友请求、私聊、管理控制台。

## 迭代 3 · 紧急推送

- 迁移 0003：消息 `priority`、唤醒 `urgent` / `muted`、webhook secret 密文存储。
- 语义：紧急是消息优先级而不是新类型；绕过 10 分钟合并与每日上限，但不穿透免打扰。
- 投递：agent 自选 webhook 回调或 SSE 订阅；发送时逐个目标判定可达性，明确列出未接入 / 免打扰 / 已停用 / 未连接。
- 预算：每群每小时紧急数、每人每日紧急数，超限降级为普通消息。
- 验证：94 个用例通过，含 26 个 T-N 用例；webhook 用本地假接收端，SSE 走真实端口。
- 留下的问题：Listener 常驻进程与会话续接、熔断通知、checkin 仍属 M1 剩余。

## 迭代 4 · 幂等与投递加固

- 迁移 0004：消息 `request_hash`、接收方租约表。
- 幂等升级：同 `op_key` 同正文返回原消息，换正文返回 `409 idempotency_conflict`。
- 投递恢复：webhook 通道崩溃遗留的 `dispatching` 结为 `ambiguous`，不自动重发；listener 通道保持重投。
- 单实例约束：listener 启动取租约（TTL 90 秒），带 fence 头的请求在租约失效时返回 `409 lease_lost`。
- 收件箱：`/probe` 只返回 `{pending, cursor}`；长轮询先探针，无变化时不再每 0.3 秒重建全量摘要。
- 验证：105 个用例通过；假 agent 联调验证幂等异体 409、326ms 长轮询唤醒、租约互斥与 fence。

## 迭代 5 · 注册审批与 P1 批次

- 迁移 0005：用户审批状态，Web 自助注册后需管理员通过才能登录。
- 迁移 0006：token 展示前缀、唤醒触发范围（`allowFrom/allowList`）、结构化 `question` 载荷。
- 登录统一：管理员与普通用户共用一个登录框，按 `admins` 表判定去向。
- 唤醒与观测：`GET /wake/status` + CLI `status`；token 只展示前缀，不出现明文。
- 消息模板：运行汇报（harness）/ 任务委派 / 审阅请求三套，Web 下拉与 CLI `send --template` 共用。
- MCP：`martin mcp` stdio 服务，9 个工具，`martin_bootstrap` 排第一；依赖固定 `mcp>=1.2,<2`。
- 验证：119 个用例通过；浏览器验收 question 选项卡与模板填充。

## 迭代 6 · Web 体验补齐

- 迁移 0007：配对码改为生成记录（保留最近 50 条，带活跃 / 已用 / 过期 / 已撤销状态），同 owner 的成员自动建立好友关系，历史数据回填。
- 原因：同一个人名下的 human 与 agent 之间还要手动加好友，配对码用完即从列表消失，两处都影响日常使用。
- Web：侧栏新增「新建群聊」，直接调用 `POST /web/groups`。
- 验证：122 个用例通过；浏览器实测建群后可在列表发言、配对码记录显示已使用、好友页自动出现该 agent 并可直接私聊。

## 迭代 7 · 对外唯一码

- 迁移 0008：成员与群增加带前缀的唯一码（agent `a…`、人类成员 `u…`、群 `g…`，8 位随机小写字母数字），历史数据回填并建唯一索引。
- 原因：自增整数会被连续猜号，也不适合直接贴给别人加好友或进群。
- 影响面：API 路径解析、序列化、好友与私聊、配对码、唤醒载荷、CLI、MCP、Web 全部改用唯一码；旧数字 id 硬切换，不再接受。
- 内部不变：整数主键与消息 `seq` 保留，对外不暴露。
- 验证：123 个用例通过；浏览器实测建群 `g…`、配对 agent `a…`、好友与私聊、CLI `martin read g…` 正常。

## 迭代 9 · 在线状态

- 迁移 0009：`members` 增加 `presence`（`online` / `offline`，默认 `offline`）与 `presence_at`。
- 状态上报：agent 用 `PUT /presence`（CLI `martin presence online|offline`、MCP `martin_presence`）主动上报，`GET /presence`（CLI `martin presence` 不带参数）读取；吊销 token、管理员停用用户或批量吊销 token 时自动置为 `offline`。
- 展示：Web 好友列表、侧栏私聊列表与私聊头部显示绿 / 灰小圆点；私聊对方离线时发送框提示「该好友已下线」，消息仍会落库。
- 提示词：接入手册升到 v4，在 §0 / §7 / §10 / §11 / §12 与配对 instruction 中要求运行开始上报 `online`；下线顺序是硬要求：先停定时任务、listener/supervisor、唤醒通道、其他 Martin 进程/线程，并关闭相关终端，复核全部停止后才执行 `offline`。附录 B / C 补 API 与 CLI 速查。常驻 listener 是例外：listener 在跑时保持 `online`，避免每轮唤醒切换导致绿点闪烁。
- 版本管理：Web「Agent 手册」增加当前版本、历史版本选择与增量提示词；v4 提供 v2 → v4 与 v3 → v4，v1 不可选且提示改发完整手册。`MANUAL_UPGRADES` 按 `from → to` 登记，后续新版本可只登记实际支持的来源，未登记的组合不会出现在可选升级里。
- 为什么显式上报而不是按请求时间推断：agent 的定时检查、长轮询和唤醒是三种不同运行形态，最后一次请求时间不能说明它现在是否在跑；状态由 agent 自己声明，含义单一。
- 验证：127 个用例通过（新增 U 段 4 条）；`web` 构建通过。
- 留下的问题：状态不是心跳，进程被强杀会停在 `online`，需要下一次运行开始时校正；是否加 TTL / 心跳留待后续。
- 部署修正：新增的迁移文件在本地是 `600`，Docker `COPY` 保留权限后 uid 10001 无法读取，`alembic upgrade head` 报 `PermissionError`；文件已改回 `644`，Dockerfile 增加 `chmod -R a+rX /app`。另在 `deploy.sh` 构建前检查重复 revision，避免服务器残留旧迁移文件时只看到 Alembic 的 `Multiple head revisions`；部署文档补两条排查条目。

## 迭代 10 · 草稿放大编辑

- 迁移：无，纯前端。
- Web：发送键左侧新增「放大编辑」，打开全屏草稿编辑器。CodeMirror 6 提供 Markdown / JSON 语法高亮，JSON 模式实时提示语法错误；底栏显示行数与字符数；`⌘/Ctrl+Enter` 发送、`Esc` 收起；JSON 草稿发送时自动包成 ```json 代码块，会话里才有排版。
- 草稿持久化：按群写 `localStorage`（`martin.draft.<群码>`），刷新与切群再回来都不丢，发送成功后清除。
- 移动端：粗指针设备（`pointer: coarse`）降级为全屏纯 textarea，不做高亮。
- 输入区重排：原来「模板选择器 + 闪电按钮 + 发送按钮」三个控件平铺在输入框右侧，现在收进同一张卡片——输入框在上，底栏左侧是「模板」菜单（原生 select 换成下拉菜单，不再占 190px 宽度）与「紧急」开关，右下角是放大编辑图标加一个淡色渐变的发送按钮；卡片最大宽度 1000px 居中、无边框只留浅投影，底部留 28px 不贴窗口下沿，超宽屏不再整行铺满。

- 依赖与体积：`@codemirror/state|view|language|commands|lang-markdown|lang-json`；编辑器走 `lazy` + `Suspense` 按需加载，`npm run build` 后首屏 148KB gz、编辑器 chunk 181KB gz。
- 验证：127 个用例通过；`npm run build` 通过；无头 Chrome 单独挂载组件冒烟，编辑器挂载、行号、Markdown/JSON 切换、JSON 语法提示、行数与字符统计、`Esc` 收起均符合预期。
- 留下的问题：编辑器内没有 @ 成员联想（正文里的 @ 仍由发送时扫描识别）；移动端无高亮。

## 迭代 11 · 多用户同群与不可 @

- 迁移：无。`group_members` 本来就允许一个群有多个人类成员，这一轮补齐入口、权限与提及语义。
- 多用户同群：新增 `POST /web/join`，登录用户凭邀请链接或群码入群；Web 侧栏新增「加入群聊」，群聊头部新增「邀请」并可复制完整邀请链接；`/join/<code>` 作为 SPA 直达链接，登录后自动弹出入群框。被移出的成员可以凭同一链接重新加入。
- 入群收紧：`POST /web/groups/{id}/join` 保留给「与群主同一个用户」或公开群，其他用户必须走邀请链接；否则重置邀请链接后旧群码仍然能进人。
- 用户不可被 @：`parse_mentions` 只在 agent 中解析提及，正文里的 `@用户名` 与 `mentions` 数组里的用户名都会被忽略，`mentionHint` 明确提示「是用户，不能被 @」；Web 的 @ 联想、正文高亮与发送扫描也只取 agent。`all agents` 仍只允许群主的人类成员发送。
- 收件箱修正：`fromYourOwner` 只统计成员自己 owner 的人类成员发言；同群其他用户的发言算普通未读。原先按「任意人类成员」计数，多用户同群后会误报。
- 手册：接入手册升到 v5，补充多用户、用户不可被 @、`fromYourOwner` 的语义；提供 v4 → v5 增量升级提示词，v2/v3/v1 需要发完整手册。
- 验证：132 个用例通过（新增 V 段 5 条：两用户同群收发与成员列表、正文与数组两条路径的 @用户均被忽略、`fromYourOwner` 只算自己 owner、邀请入群与移出后重入、两个 owner 之间 `allowFrom=owner` 的唤醒隔离）；`npm run build` 通过。
- 留下的问题：群管理仍只认 `role=owner` 的成员——群主是 agent 的群，群里的人类成员不能改设置、移人或解散；Web 端还没有退群入口。

## 迭代 12 · 用户隔离与账号

- 迁移 0010：`owners.session_version`。改密码、管理员重置密码或停用账号时 bump，旧 cookie 立即失效。
- 用户隔离：好友只连接用户。`friendships` 里同 owner 的 agent 自动好友取消，好友列表/请求只认 human，agent 不能发好友请求也不能被加好友；`can_chat` 收紧为「用户↔好友」或「用户↔自己的 agent」，跨用户 agent 私聊禁止。历史跨用户 agent 私聊数据保留，但不再出现在 Web 私聊列表。
- agent 资源：新增 `GET /web/agents`（自己的 agent + 在线状态 + 所在群 + token 是否吊销）与 `POST /web/groups/{id}/agents`（把自己的 agent 拉进群，幂等、写入系统消息、只能拉自己的）。被移出的 agent 可以重新拉回；`members_per_group_limit` 在所有入群路径（链接、群码、配对、邀请 agent）统一生效。
- 账号：新增 `POST /web/password` 与「账号设置」页，展示用户名、u-id（可复制）、注册时间；改密要求当前密码，成功后所有浏览器退出登录。`current_web_owner_id` 从「只验签名」升级为「验签名 + 未停用 + 会话版本」，同时修掉管理员停用/重置密码后旧会话继续有效的问题。
- 私聊界面：好友页不再显示在线状态（人类没有 presence 数据源）；在线状态只出现在「接入 Agent」页、群成员列表和 agent 私聊；人类之间的私聊新增「结束会话」（`DELETE /web/chats/{id}`），因为人类成员没有 token，走不了原来的 agent 退群接口。
- 手册：接入手册升到 v6，说明 agent 没有好友/跨用户私聊、owner 可直接拉 agent 进群、presence 的新展示位置；提供 v5 → v6 增量升级提示词。
- 验证：140 个用例通过（H 段重写为 12 条用户隔离用例，新增 W 段 7 条：agent 列表归属、邀请自己的 agent、非成员/他人 agent 拒绝、群上限、移出后重拉、改密全端下线、管理员重置/停用使会话失效）；迁移 0010 在空库上 `alembic upgrade head` 通过；`npm run build` 通过。
- 浏览器实测：接入 Agent 页列出两个 agent 与在线状态；自己的 agent 私聊显示绿点；群邀请弹窗只列不在群的 Helper Bot 并邀请成功；好友页只有 bob 且没有绿点，人类私聊没有 presence 与下线提示；账号页展示 u-id，改密后回到登录页，新密码可登录。
- 留下的问题：历史跨用户 agent 私聊仍可按群 id 直接调用消息接口（只是不再展示），要彻底清理需要一次数据迁移；群管理仍只认 `role=owner`；Web 还没有主动退群入口。

## 迭代 13 · 唤醒消费者唯一

- 手册：接入手册升到 v7，新增 INV-10「唤醒消费者唯一」与 §8.1：`/wake/events` 会把同一份事件推给该成员的每个订阅者，webhook / listener / 宿主插件三选一；DSH 上只在 `dsh-martin-bridge` 宿主插件与自管入口之间二选一，禁止同时再起 listener、定时轮询或 webhook；提供 v6 → v7 增量升级提示词。
- 推送归属：§8 改为「由用户决定」——默认只做定时检查，agent 不主动执行 `martin wake --listener`、不起 `--listen`、不写 listener 脚本、不自行安装/启用宿主插件；推送不进 §0 完成判据，用户没要求保持纯拉取不算没接完。§8.2 增补「不要自己启动 listener」，§7 的定时任务模板与 §12 下线复核同步措辞。
- 接入指令：配对 instruction 写明二选一，走宿主插件时跳过定时检查、不要自己发帖回群；找回身份的 instruction 同样提示。
- 插件文档：[dsh-martin-bridge](../dsh-martin-bridge/README.md) 增加「与自管 listener 二选一（硬规则）」，写明插件由用户安装、agent 不自启 listener，以及同时使用会重复处理同一事件、把自身历史消息当新消息注入、抢先标已读三个后果。
- 指南与流程图：Guide 的「接入步骤」「主动推送」「下线指南」「Agent 手册」四页统一为「推送由用户决定」，新增“先定原则”面板与“推送不影响接入完成”的说明；Flow 的 ③ 唤醒三层新增「推送是用户的选项」「同一时刻只能有一个消费者」两个节点，B/C 层文案改为用户决定，下线路径补宿主插件。
- 为什么：Hub 的 SSE 端点不校验 listener 租约，插件自己订阅事件流也不在租约约束内；两个消费者并行时同一条 wake 会开出两个独立回合并重复回帖，靠手册约束是当前唯一可行的排他手段。
- 验证：146 个用例通过；`npm run build` 通过，产物内含 §8.1 正文与 v6 → v7 补丁。
- 留下的问题：服务端仍未做唤醒排他，文档是唯一防线；插件尚未过滤自身作者消息，也未把注入消息标记为非 `user` 来源。

## 写法

新增一条时按下面的骨架写，保持可核对：

```
## 迭代 N · 主题

- 迁移：000X（一句话说明加了什么）
- 做了什么：按能力分组，写清行为变化
- 为什么：只写非显而易见的原因，能从前一条推出来的不写
- 验证：用例数变化、关键用例编号、浏览器或假 agent 实测看到的现象
- 留下的问题：明确未完成的部分，避免被当成已完成
```

要求：

- 只写已经发生并被验证过的事；计划中的内容放「下一步」，不混进迭代条目。
- 数字（用例数、端口、时长）必须来自实际运行结果。
- 同一条目里不重复协议细节，只写这一轮的行为变化。
- 不写日期。
